# Director creative authority: initial implementation audit

This change removes only the following managed/Responses Director proposal checks: prefixes naming a speaker or role, leading/trailing whitespace, identical first and second messages, and a fixed ban on the words execute, kill, murder, torture and sudo in speech and quoted notes. Original UTF-8 text is preserved and the existing whole-proposal provider moderation remains mandatory. Other adapters and scripted modes are unchanged. The old word filter remains for non-Director text.

This is an intermediate change, not completion of the owner directive. An explicit, separately run migration now permits the first two distinct participants to speak in either order and either validated participant to speak thereafter; it preserves historical rows, and schema/managed-session scope and public projections recognize the capability. Director-selected pairs no longer face the friendship-cap veto, and saving Director dialogue no longer creates or changes relationship scores. Director notes are no longer silently dropped at the legacy per-resident receipt cap. The following existing decisions remain and need coordinated implementation and review:

- Participant selection: managed Director selection chooses a validated pair; the flexible-speaker capability now fails closed if that selection is disabled, while legacy/default-off selection and short-term continuation can still choose the pair in PHP when that capability is absent. Selection admission, available residents, rest and accounting are separate technical/owner-policy checks. The production environment was not inspected or modified.
- Dialogue structure: legacy `messages` supports exactly two distinct speakers. Extended messages require two to 64 messages, the first two from different participants in either order, and at most 160 characters per message. With the separately migrated capability, subsequent messages can use either validated participant; without it strict alternation remains. These are schema checks and triggers as well as PHP validation. A new append-only, versioned storage contract plus archive, journal, commons, lineage, memory, moderation and accounting changes are needed to support arbitrary speaker order or length without rewriting history. Configured v2 min/max, the output budget and session contract must be reconciled too.
- Text: Director text now preserves markup-like text, URLs and instruction-like prose; public renderers must continue escaping it and context marks prior text as untrusted. UTF-8, NUL and existing storage lengths remain technical constraints; credential-like patterns remain blocked to protect secrets. Legacy non-Director text validation is unchanged.
- Stories: the Director chooses start/continue/conclude/revisit/none from a bounded set of eligible stories. Verified public story heads can now be offered without a prior participant; public reference is explicitly not attributed to new participants. PHP validates state and requires accepted conversation for a state change; the stored ledger enforces transitions. Those rules exclude some authorized creative choices and require a revised provenance, privacy and persistence contract, rather than inferring relationships retroactively.
- Continuity: existing selection can offer a bounded same-pair follow-up for up to three segments, even though separate explicit narrative stories can extend longer. The Director is not yet sole authority over that selection.
- Memory: An explicit additive memory capability lets the Director write original, unverified recollections for actual participants without quote matching, classification or a per-resident storage cap; quiet outcomes can retain memories too. Retrieval remains bounded and holder-scoped. Legacy Director notes remain available and older non-Director paths still manufacture memories.
- Relationships: `strengthen` and relationship limits remain in non-Director activity and fallback selection, but Director dialogue no longer mutates relationship scores and managed AI-selected handoff no longer applies the friendship cap. They are PHP-authored behavioral state, not a necessary property of saving speech. Removing them needs changes to selection and old consumers without destroying historical data.
- Topics and scripted paths: the Director topic is preserved in `director_runs`, while legacy conversation rows use the compatibility topic `welcome`. Older scripted and non-Director paths still contain templates. Those paths have not been removed.
- Narrative guidance and operational configuration: PHP still supplies guidance and has defaults and structural ceilings in multiple components. Some limits protect bounded input, execution and accounting; others are owner policy. A complete ENV migration needs an inventory and explicit invalid/missing-setting behavior, while preserving historical accounting commitments and deployment compatibility.
- Retained safety/integrity: participant foreign keys, exact source attribution, transaction rollback, authenticated transport, request intents, uncertain holds, moderation, lease fencing and idempotency remain unchanged. No production data, configuration, timers or paid APIs were touched.
